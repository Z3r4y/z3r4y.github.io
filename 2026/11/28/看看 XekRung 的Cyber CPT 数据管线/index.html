看看 XekRung 的Cyber CPT 数据管线

Z3r4y
2026-11-28
Paper Reading
LLM Security, LLM Training, Paper Reading

1. Intro

论文：XekRung Technical Report
链接：arXiv:2605.00072 · v1 2026-04-30 / v2 2026-11-06
机构：Alibaba Security AGI Lab
流水线：Qwen3-8B → CPT（5B token）→ mid-training → SFT（约 30 万条）→ RL（约 12 万条 prompt，GRPO）

2. 语料来源

论文列了五类语料：开源与外部数据、内部产品数据、内部知识文档、日志数据、代码数据。其中内部产品数据、内部知识文档、日志数据三类是内部资产。

内部资产还有两条额外用法：日志数据被单独拿来抽知识、建知识图谱，与 top-down 的行业标准和专家框架持续互校；内部知识文档里的专家经验被蒸馏成 chain-of-thought 训练数据（但个人感觉不是很work）。

3. 素材 → CPT 数据

论文描述的素材到样本的转换共九条，可归为三组：样本合成四条，把各类原料改造为训练样本（本节）；内部资产转化两条，把内部日志与专家文档里的内容抽出来用（上一节）；阶段注入三条，在 CPT 与 SFT 之间的专门窗口内注入（下一节）。

前置 · 每份原料都要过一遍
通用处理管线：精确去重（文档哈希）+ 模糊去重（MinHash）→ 质量过滤（长度／语种／困惑度启发式，叠加专家正负样本训出来的分类器）→ 脱敏（PII、内部资产标识、base64 块、URL 追踪参数、session token）→ 格式归一（HTML／PDF／Markdown／结构化日志统一成纯文本，代码块与结构化字段原样保留）。

3.1 解释性标注：把工具输出翻译成教材

通用预训练语料里极度 underrepresented 的安全产物：IDA Pro / Ghidra 反编译伪代码、原始 shellcode 与 ROP gadget 链、PCAP 拆解、Suricata / Snort / YARA 检测规则、eBPF 内核追踪、调试器会话、fuzzer 崩溃报告。

它们的原始形态是内存地址、十六进制字节、领域专用语言 token，直接喂进去表征学习效率极低。

解法：每个原始产物配一段合成生成的自然语言解释，讲清语义、安全含义和操作语境，把专业工具输出转成语义自足的训练样本。

不是所有安全知识都能以它原本的形态进入预训练。反编译结果该以「反编译结果」的形式学，还是该以「这段反编译结果说明了什么」的形式学，这是两个完全不同的效果。

3.2 关联信息聚合：按语义锚点聚类

CVE 描述、PoC 代码、威胁情报报告语义上强关联，但天然散在异构仓库里。论文的做法是绕开随机采样，以共享语义锚点（CVE 编号、具体软件组件）为中心聚合文档，三步由粗到细：

  1. 层次语义聚类 — 靠稠密向量相似度，把文档从宽泛的安全域逐级切到事件级分组
  2. 互补性感知组装 — 在细粒度组内构造训练窗口，在「语义连贯」和「产物类型多样」之间取平衡
  3. 按信息量重排前置 — 估计每篇文档的信息量，最有信息量的放序列最前面。理由是 primacy bias：靠前的 token 被后续 token 关注更多

以漏洞域为例（按它的三步推演）：以某个 CVE 编号为锚点，窗口里放漏洞函数的反编译伪代码、对应修复 patch 差分、CVE 公告文本、触发条件、同族变体。互补性在这里是有内容的——伪代码和 patch 语义高度重叠，讲的是同一件事；patch 和 CVE 描述互补，一个讲怎么改、一个讲为什么严重、影响面多大。所以「语义连贯 + 类型多样」实际是在同质多视角和异质依赖之间找平衡。信息量前置的直觉也顺：CVE 公告含编号、CWE 线索、影响面，放最前，后面所有文档都能关联上。

3.3 EntropyLong：熵引导长上下文

借 EntropyLong（arXiv 2510.02330，ICLR 2026）的原理并做了扩展。四步：

  1. 前向传播定位预测熵超过动态阈值的锚点——把「模型猜不出来」当信息缺口的代理信号
  2. 用锚点的局部上下文检索候选段落
  3. model-in-the-loop 验证：候选前置后重算锚点位置熵，只留能把熵压掉 40% 以上的
  4. 打乱后拼到源文档前面

它把「这段拼接有没有用」从主观判断变成了可量化验收。 语义检索会大量捞回「关键词命中但没补上缺口」的段落——用余弦相似度排序，排在最前面的往往正是这类。判据换成「锚点位置的熵降没降」，就只剩真依赖。

3.4 工程经验编排：代码差分、commit 轨迹、迭代自纠错

前三条改的是已有文档和产物：翻译成自然语言、按语义锚点聚成窗口、按熵降挑长上下文拼接。这部分的原料不是文档，是代码库的演进史——一次 diff、一条 commit 链、一轮迭代修订。

最高价值的知识很少以陈述句存在，它藏在真实代码库的演进史里。三级递进：

切法 做法 模型学到的东西
静态代码Diff 漏洞代码 + 对应 patch + 修复后输出配成对 不只是预测补丁文本，而是推断改动的语义意图
提交轨迹建模 按时间顺序组织 commit 序列 从故障发现 → 根因定位 → 补丁生成的完整推理链
迭代自纠错轨迹 收录 patch 反复修订、review 意见被逐条回应 显式监督错误恢复

一次 diff 是一个点的快照，一条 commit 链是一段过程，一次迭代是一轮收敛。这种迭代的数据是自动漏洞修复与代码审计不可或缺的监督信号。

4. Mid-Train 阶段注入

论文在 CPT 和 SFT 之间开了一个 Mid-Train。 mid-training 的三条注入路径：

  1. 长程 agentic traj — 数据就是 agent 轨迹，论文自己加的只有两样：序列化成 O-T-A（observation-thought-action）格式，以及控制注入节奏。覆盖自动化渗透测试、大规模漏洞发现与验证、红队长链攻击模拟、多阶段事件响应。注入节奏两条：占比随训练步数 sigmoid 爬坡（α_agent(t) = α_min + (α_max − α_min)·σ((t − T_mid/2)/τ_warm)），轨迹长度从短到长；多步渗透轨迹动辄数万 token，一上来就训全长会梯度不稳
  2. 仓库级长上下文代码 — 跨文件调用关系、模块依赖、接口契约。理由是真实的漏洞定位与修复本来就跨文件，孤立片段训出来的是 snippet 级别的能力
  3. 线性化 SFT 数据 — 剥掉 chat template 与 role marker，重写成纯文本续写序列，用同一个自回归 LM 目标训，不提前把指令-回答格式焊死
