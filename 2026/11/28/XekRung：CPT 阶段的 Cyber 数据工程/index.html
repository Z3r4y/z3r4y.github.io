XekRung：CPT 阶段的 Cyber 数据工程

Z3r4y
2026-11-28
Paper Reading
LLM Security, LLM Training, Paper Reading

1. 论文信息

论文：XekRung Technical Report
链接：arXiv:2605.00072 · v1 2026-04-30 / v2 2026-11-06
机构：Alibaba Security AGI Lab
基座：Qwen3-8B → XekRung-8B，刻意做成 non-thinking
流水线：Qwen3-8B → CPT（50 亿 token）→ mid-training → SFT（约 30 万条）→ RL（约 12 万条 prompt，GRPO）
开源状态：闭源。HuggingFace 搜 XekRung 返回空，没有权重、没有 model card、没有训练与评测代码。

我上一篇写 MiST 的 mid-training 数据合成，这篇正好是它的另一半：同一个领域里，一篇把中间语料当「合成问题」解，一篇把中间语料当「语料工程问题」解。两篇零引用。

先说结论：这篇报告的方法论野心很大，但它宣称的那个 mid-training 阶段，从来没有进入它的结果口径，也从来没有被消融。 真正值得读的是 §3.1.3 的四个领域策略——那才是 CPT 的主体，也是可抄的部分。

2. 五类语料：清单不是重点，难表示才是

§3.1.1 列了五类：开源与外部数据、内部产品数据、内部知识文档、日志数据、代码数据。

值得注意的不是「有五类」，而是三件事：

  • 三类是内部资产：内部产品数据（检测规则描述、告警元数据、威胁情报条目、产品分析报告）、内部知识文档（专家写的检测方法论、事件响应手册、分析师维护的知识库）、日志数据（网络、端点、应用层真实遥测）。这三类外部拿不到，也是它比同类工作更难复现的部分。
  • 它把日志当知识来源，不是当数据来源：原文说自顶向下（行业标准 + 专家框架）加自底向上（从真实运营日志里自动抽取知识、建知识图谱），两条持续互相校准。
  • 全文 proprietary 出现 7 次。

但 CPT 的真正难点不是「收集」，是「表征」。 下一节。

3. 四个领域策略：§3.1.3 是这篇报告真正的资产

论文自己说统一管线解决了通用数据质量问题，但安全语料还有三个域特有的坑：关键产物类型数据稀疏、语义关联的情报碎片化、真正的长程依赖不会被朴素文档拼接捕获。对应四个补丁。

3.1 解释性标注：把工具输出翻译成教材

通用预训练语料里极度 underrepresented 的安全产物：IDA Pro / Ghidra 反编译伪代码、原始 shellcode 与 ROP gadget 链、PCAP 拆解、Suricata / Snort / YARA 检测规则、eBPF 内核追踪、调试器会话、fuzzer 崩溃报告。

问题不在于它们少，在于它们长这样：内存地址、十六进制字节、领域专用语言 token。直接做表示学习效率极低。

解法：每个原始产物配一段合成生成的自然语言解释，讲清语义、安全含义和操作语境，把专业工具输出转成语义自足的训练样本。

这一招的通用价值在于它承认了一件事：不是所有安全知识都能以它原本的形态进入预训练。反编译结果该以「反编译结果」的形式学，还是该以「这段反编译结果说明了什么」的形式学，这是两个完全不同的训练问题。

3.2 关联信息聚合

CVE 描述、PoC 代码、威胁情报报告语义上强关联，但天然散在异构仓库里，随机拼接接不上。

论文没给具体做法。 这是四个策略里唯一只给了问题描述、没给机制的。

3.3 熵引导长上下文：最值得抄的一段

它借的是 EntropyLong（arXiv 2510.02330，ICLR 2026）的原理并做了扩展。四步：

  1. 前向传播定位预测熵超过动态阈值的锚点——把「模型猜不出来」当信息缺口的代理信号
  2. 用锚点的局部上下文检索候选段落
  3. model-in-the-loop 验证：候选前置后重算锚点位置熵，只留能把熵压掉 40% 以上的
  4. 打乱后拼到源文档前面

（上面是原论文的 Figure 1。XekRung 在 §3.1.3 与 §4.2.2 各用了一次。）

这一步为什么重要：它把「这段拼接有没有用」从主观判断变成了可量化验收。 语义检索会大量捞回「关键词命中但没补上缺口」的段落；判据换成「锚点位置的熵降没降」，就只剩真依赖。

但有两个坑得自己处理：

  • 原文是前置，XekRung §4.2.2 写成追加。 后置在前向传播里帮不到锚点位置的预测，「降低熵」这个机制直接不成立。按 §3.1.3 和 EntropyLong 原文，是前置。
  • 没讨论检索到根文档自身片段的情况。 全文 duplicate / overlap / decontamination 零命中，而检索库和源文档同源。如果候选恰好是根文档的复制品，熵一样会降，ΔI 一样很高、一样被留下——那就构造出一条「把答案抄在前面」的平凡依赖，根本不需要长程检索能力。复现时得自己加一层重叠过滤。

3.4 工程经验编排：三种时间尺度

最高价值的知识很少以陈述句存在，它藏在真实代码库的演进史里。三级递进：

切法 做法 学到的东西
静态代码差分 漏洞代码 + 对应 patch + 修复后输出配成对 不只是预测补丁文本，而是推断改动的语义意图
提交轨迹建模 按时间顺序组织 commit 序列 从故障发现 → 根因定位 → 补丁生成的完整推理链
迭代自纠错轨迹 收录 patch 反复修订、review 意见被逐条回应 显式监督错误恢复

三种切法对应三种时间尺度：一次 diff 是一个点的快照，一条 commit 链是一段过程，一次迭代是一轮收敛。论文明确说第三种是可靠自动漏洞修复与代码审计不可或缺的监督信号——而它恰好是最难从公开数据里拿到的一类。

3.5 整个语料工程的形状

4. mid-training：设计得最细的一段，却没进结果口径

§3.2 是这篇报告论证最用力的一节，也是全文唯一给出数学形式的地方。

为什么要有这个阶段：这类高阶能力（长程规划、多步工具调用、仓库级代码推理）注入太早会干扰通用语言建模目标的收敛，注入太晚（基座能力固化后）又吸收次优。所以它在 CPT 和 SFT 之间开一个专属窗口。

三类数据 + 一条课程：

  • §3.2.1 长程 agentic 数据注入：O-T-A 格式，目标任务点名自动化渗透测试、大规模漏洞发现与验证、红队长链攻击模拟、多阶段事件响应。课程是两维的——比例维用 sigmoid 动态爬坡，α_agent(t) = α_min + (α_max − α_min)·σ((t − T_mid/2)/τ_warm)；长度维短到长渐进，因为多步渗透轨迹动辄数万 token，一上来就训全长会梯度不稳。
  • §3.2.2 仓库级长上下文代码：跨文件调用关系、模块依赖、接口契约。
  • §3.2.3 线性化 SFT 数据：剥掉 chat template 与 role marker，重写成纯文本续写序列，用同一个自回归 LM 目标训，目的是不提前把指令-回答格式焊死。

然后是问题所在：

位置 口径
§3 mid-training 出现 9 次，专章论证
§5 Training Setup “three-stage pipeline”，checkpoint 链是 base → CPT checkpoint → SFT checkpoint → RL
Table 1 / §5 分析 / §6 结论 全部写 CPT → SFT → RL

mid-training 在 §4 之后一次都不出现。它被设计、被论证，却没有对应的 checkpoint，没有数据量，没有步数，没有隔离消融。

所以 +9.03 这个数字归因不到 mid-training 头上。 它可以是 CPT、SFT、RL 三者加上一个未披露阶段的混合产物。

顺带一个笔误级别的细节：§3.2 正文说 “we incorporate four data and scheduling strategies”，紧接着只列了 (1)(2)(3)。

5. 81.04 分是怎么来的

Table 5 的 15 行我逐行复算过，能复现论文的 Overall Avg：基座 72.01 → XekRung 81.04。

增益极度集中，而且集中在与 RL 奖励重合的那几项。

  • 总增益 135.55 分，CTIBench 四项贡献 111.63 分，占 **82.4%**；这四项只占基准数的 4/15。
  • 其余 11 项从 79.85 到 82.03，平均只涨 +2.17。
  • §4.4.1 定义的三个 RLVR 奖励是 Root Cause Mapping（从 CVE 语义预测 CWE）、Vulnerability Severity Prediction（预测 CVSS 向量）、ATT&CK Technique Extraction（从威胁情报抽 ATT&CK 技术）。Table 5 里 CTIBench-RCM / VSP / ATE 的描述与这三个奖励一一对应。ATE 从 25.41 到 73.39，是全表最大单项。
  • 全文检索 contamination、decontamination、held-out、leakage，零命中。

领先项的口径要说清楚：论文的加粗是「≤14B 模型中的最佳」。按这个口径 XekRung 领先 6/15——CTIBench 四项，加 SecEval 和 CyberMetric-500Q。把 Llama-3.3-70B 也算进来，领先项就只剩 4 个，全是 CTIBench（70B 拿走了 SecEval 73.79 和 CyberMetric-500Q 94.20）。

还有一层：支撑 mid-training 必要性的那些能力，论文自己说还没测。 §5.2 明写 agentic 与 code-level 基准正在集成中，将随更大规模模型一并报告。也就是说 §3.2 论证的收益，在这份报告里是声明而不是结果。

6. 启发：CPT 到底该怎么验收

这篇的方法层值得抄，结果层不能直接引。留下三条：

一、给合成数据造一个可量化的验收信号。
熵引导的启示不是「用熵」，是「找一个模型自己内部的、可量化的信号，来给合成数据做质检」。CPT 最贵的成本不是造数据，是判断造出来的东西有没有用。XekRung 在这一层给了完整可复刻的模板（阈值、候选数、验证公式），而它的下游——§4.2.3 用 LLM-as-Judge 给数据打连续分——是同一思路的另一种实现。

二、奖励任务和评测任务不能是同一批。
XekRung 把 CTIBench 的 RCM / VSP / ATE 同时当 RL 奖励和评测题，又没有任何污染讨论。这是它 81.04 里最不可信的部分。MiST 的做法可以直接抄：把这几个 split 锚定的 CVE 记录从种子语料里剔掉，再叠 13-gram 去污染（整体移除约 3.78%）。把 CTIBench 家族当 RL 奖励用，这两步不是可选项。

三、每个阶段都要有隔离实验，否则它等于不存在。
XekRung 缺的那张表——CPT only / +mid-training / +SFT / +RL——是任何领域 CPT 都该有的第一张表。缺了它，你没法知道增益来自哪一层，也就没法判断这条流水线里哪一段值得投钱。

7. 结语

XekRung 的处境挺特别：它是目前公开材料里把安全领域 CPT 做得最细的一份，§3.1.3 那四个策略尤其值得看——但它的结果是在「奖励与评测重合、且没有污染控制」的设置下测出来的，而它自己最想论证的那个阶段（§3.2 mid-training）没有进入结果口径。

所以引用姿势是：方法可以抄（尤其熵验收这条），数字必须带条件引用。

补一句：这篇和上一篇 MiST 是零引用的平行工作——一个把中间语料当合成问题解，给了干净的 +4.8 隔离实验；一个把中间语料当语料工程问题解，给了完整的领域策略但没给归因。两篇合起来看，cyber 方向 mid-training 的方法论地图才算完整。
